# Заказы 0.4

Нативное Android-приложение Lift-ZIP для локального учёта оплаченных заказов, расчётных групп и истории цен. Работает без сервера, регистрации, MAX и электронной почты.

Это тестовый устанавливаемый прототип. Фактические результаты сборки и проверок конкретного коммита доступны в GitHub Actions. Правила новых отметок и проверки описаны в [0.4](docs/GROUP_FULFILLMENT_0.4.md); прежний контур доставки — в [0.2](docs/DELIVERY_AND_UI_0.2.md).

## Что изменилось в 0.4

Компактная таблица группы по согласованному макету помещается на экран: заказ, суммы Д/К/∆ и три независимые отметки «Снял», «Передал», «Получено». Отметки сохраняются сразу; все три по каждому заказу автоматически переводят сформированную группу в «Выполнена». Снятие любой отметки возвращает «На расчёте». Суммы от отметок не меняются. [Правила и проверка](docs/GROUP_FULFILLMENT_0.4.md).

## Что изменилось в 0.2

Компактная карточка заказа, сохранение сверху, отдельный прогноз доставки по позициям и отдельный счёт/журнал расчётов с клиентом и логистом. [Описание и ограничения](docs/DELIVERY_AND_UI_0.2.md).

## Основа 0.1

- Вкладки «Заказы», «Группы», «История цен»; выбранная вкладка сохраняется. Начальная вкладка — «История цен».
- Создание и редактирование заказа с несколькими позициями, поиск и повторное использование товаров.
- Явная оплата, запрет автоматического исправления частичной оплаты, подтверждение нулевой цены.
- Закупка RUB/CNY, сохранённый курс, расходы позиции/заказа/группы, предварительная прибыль и признак неполного расчёта.
- Автоматическое включение заказа в формируемую группу; атомарное и идемпотентное завершение набора.
- После завершения набора заблокированы состав и выручка; закупочные поля, расходы и комментарий можно уточнять.
- Фактические продажи и черновые закупочные расчёты в истории товара без дублирования записей при редактировании.
- Экспорт/восстановление через Storage Access Framework. ZIP содержит `manifest.json`, `data.json`, SHA-256 данных, версию схемы и количество записей. Архив **не зашифрован**.
- Проверка архива до замены, локальная копия перед импортом и возможность восстановить её из настроек.
- Недеструктивная миграция Room 1→2, экспортируемые схемы, запрет деструктивного fallback.
- Системные облачные резервные копии отключены.

## Модули

- `:core:domain` — модели, BigDecimal-расчёты, проверка инвариантов, интерфейс репозитория. Без Android и Room.
- `:core:data` — Room/SQLite, транзакции, миграции, реализация репозитория, резервные копии.
- `:app` — Compose, MVVM, StateFlow, навигация и Storage Access Framework.

Все сущности имеют UUID. Видимые номера заказов и групп отдельны и последовательны. Денежные суммы в БД — `Long` в копейках; количество, курс и закупочная цена — канонические decimal-строки. В UI нет SQL и денежных формул.

## Требования для сборки

- JDK 17.
- Android SDK: Platform 35; AGP 8.7.3 использует Build Tools 34.0.0 по умолчанию.
- Android 8.0 или новее для запуска (`minSdk 26`).
- При первой сборке Gradle загрузит зафиксированные зависимости из Google Maven/Maven Central. Самому приложению сеть не нужна.

Версии зафиксированы: AGP 8.7.3, Kotlin 2.0.21, Gradle 8.9, Room 2.6.1, compile/target SDK 35. Динамические версии не используются.

## Сборка

Укажите SDK через переменную `ANDROID_HOME` или скопируйте `local.properties.example` в `local.properties` и задайте `sdk.dir`.

Linux/macOS:

```bash
chmod +x ./gradlew
./gradlew :app:assembleDebug
```

Windows:

```bat
gradlew.bat :app:assembleDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`.

Используется официальный Gradle Wrapper 8.9 с проверкой SHA-256 дистрибутива. Самодельный загрузчик удалён.

## Проверки

Доменные JVM-тесты:

```bash
./gradlew :core:domain:test
```

Instrumented-тесты Room, миграции, идемпотентности и резервного копирования — на эмуляторе или устройстве:

```bash
./gradlew :core:data:connectedDebugAndroidTest
```

Полная сборка и JVM-тесты:

```bash
./gradlew :app:assembleDebug :core:domain:test
```

Реальную проверку на Xiaomi 15 выполняет Дмитрий. Отсутствие device-теста не выдаётся за подтверждённую работу на устройстве.

## Резервная копия

«Настройки и копии» → «Экспортировать копию» / «Проверить и восстановить копию». Импорт — замена, не слияние. Дата успешной копии записывается только после закрытия выходного потока. Фоновое расписание не реализовано и не обещается.

## Ограничения 0.1

Нет денежных переводов, возвратов, взаимозачётов, утверждённых снимков, финального финансового закрытия, самостоятельных предложений, интеграций MAX/почты/OpenCart и серверной синхронизации. «На расчёте» не означает утверждённый расчёт или подтверждённый выкуп. Прибыль заказа показывается без скрытого распределения групповых расходов.

Фактические результаты проверок и ограничения среды смотрите в `REPORT.md`.
