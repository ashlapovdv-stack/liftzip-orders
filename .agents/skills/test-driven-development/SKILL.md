# Поведенческие тесты

1. Выбрать наблюдаемое поведение и независимый ожидаемый результат. Не копировать формулу или алгоритм реализации в ожидаемое значение теста.
2. Для существенного изменения логики или регрессии сначала написать минимальный тест. Проверить, что он падает на исходной реализации по нужной причине, а не из-за ошибки окружения или синтаксиса.
3. Реализовать минимальное системное исправление; выполнить тест и относящиеся к изменению проверки проекта. Рефакторинг выполнять при зелёных проверках.
4. Проверять границы, null и ноль, повторную операцию, отмену и ошибки там, где это влияет на задачу. Изоляцию организаций и миграции проверять реальным хранилищем соответствующего типа.
5. Не писать тесты ради числа тестов для текста, документации и обратимых косметических изменений. Использовать подходящую проверку ссылок, синтаксиса или визуальный сценарий.
6. Не удалять чужую работу ради соблюдения порядка TDD. Если тест добавлен после изменения, честно указать это; при необходимости доказать регрессию в отдельной копии исходного коммита.
7. Если исполнитель не может запускать проверки, подготовить тесты и точные команды, явно передать проверку интегратору. Не объявлять тесты пройденными.
Не отключать проверки, не ослаблять ожидаемые результаты ради зелёной сборки. Успешные проверки повторять только после новых изменений, сбоя или обнаружения непроверенного риска.
