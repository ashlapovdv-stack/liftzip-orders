# Android и Compose

1. Читать Gradle, текущую архитектуру и компонент перед правкой. Для конкретных API использовать официальную документацию версии проекта; не обновлять зависимости попутно.
2. Держать вычисления и I/O вне композиции и главного потока. Соблюдать lifecycle и отмену coroutine; не создавать конкурирующих владельцев одного состояния.
3. Различать состояние модели, временное UI-состояние и сохраняемое состояние. Сохранять стабильные ключи элементов, положение списка и навигационные контракты.
4. Проверять insets, клавиатуру, системную навигацию, размеры шрифта и TalkBack. Дать понятные подписи кнопкам-иконкам и состояние раскрытия.
5. Для AndroidView/WebView учитывать реальный lifecycle, размеры viewport, scroll и scale. Не пересоздавать просмотрщик при каждой рекомпозиции и не компенсировать ошибку произвольными смещениями.
6. Проверять поведение жестами на эмуляторе для затронутого UI; модульные тесты не доказывают отсутствие рывков и перекрытия слоёв. Сверять рабочие команды с .ai/PROJECT.md.
