# Проверка результата

1. Для каждого существенного утверждения выбрать доказательство: команда, exit code, отчёт CI, артефакт, воспроизводимый сценарий или результат API.
2. Проверить, что доказательство относится к текущему коммиту и его конфигурации. Использовать уже выполненную успешную проверку этой версии; не повторять её без изменения или новой причины.
3. Прочитать итог и ошибки, проверить число выполненных тестов, пропуски и реально созданные файлы. Компиляция тестового APK не означает выполнение device-тестов; lint не доказывает успешную сборку.
4. Сопоставить критерии задачи с результатом. Разделять «реализовано», «собрано», «проверено на эмуляторе», «проверено пользователем» и «загружено».
5. При отсутствии нужного окружения назвать конкретное ограничение и непроверенную часть. Не заменять фактический результат словами «должно работать».
6. Перед публикацией проверить diff, ветку, область изменений и отсутствие секретов. После записи прочитать удалённый результат и сопоставить с подготовленным содержимым.
Завершать коротким отчётом: что изменилось, какие проверки действительно выполнены, ссылка на результат, существенные ограничения.
