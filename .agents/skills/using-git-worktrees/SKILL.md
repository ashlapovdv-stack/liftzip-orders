# Изоляция веток

1. Проверить git status, текущую ветку, HEAD, worktree list, git-dir и git-common-dir; учесть submodule. Не считать пустой список изменений доказательством правильной базовой ветки.
2. Сохранить чужие незакоммиченные файлы. При существующей изолированной копии использовать её, если она соответствует задаче.
3. При необходимости создать отдельную ветку/рабочую копию от проверенного коммита в рамках порученной разработки. Предпочитать штатное средство среды; вручную использовать git worktree только если оно отсутствует.
4. Для каталога внутри проекта проверить исключение через git check-ignore. Для путей использовать корректное shell quoting. Не переносить секреты и локальные базы в новую копию автоматически.
5. Не выполнять reset --hard, clean -fdx, force push, удаление чужих веток и произвольное stash. Не менять общие git-настройки.
6. Применять только относящиеся к задаче файлы; перед push сверить remote, base и head. При перемещении удалённой ветки перечитать её состояние и интегрировать изменения без перезаписи.
Не создавать отдельную рабочую копию и не запускать полную сборку только ради небольшой правки документации, если текущая среда уже безопасно изолирована.
