# Выпуск результата

1. Определить точный репозиторий, ветку, SHA, тип выпуска и место выдачи из задачи. Сверить команды с текущей конфигурацией проекта.
2. Для APK соблюдать порядок: изменения → относящиеся к задаче автотесты/lint → сборка → необходимая проверка эмулятора → проверка подписи и обновления → загрузка → проверка ссылки. Компиляция androidTest не является прогоном на устройстве.
3. Сохранять applicationId и действующую подпись для обновления установленного приложения. Не создавать новый ключ на каждую сборку. Приватный ключ, пароль и base64 ключа не добавлять в Git, публичные артефакты и отчёты.
4. Проверить versionCode, versionName, размер APK, SHA-256 и сертификат доступными средствами. Не предлагать удаление приложения с данными вместо исправления несовместимой подписи.
5. Для данных и сервера подготовить резервирование, проверку восстановления, миграцию и откат. Не запускать production-деплой по просьбе только отредактировать инструкции или провести аудит.
6. Выполнять фактическую публикацию только в пределах уже данного поручения. Google Диск использовать, когда он указан и доступен; иначе честно назвать ограничение и выдать доступный результат без ложного заявления о загрузке.
7. После загрузки проверить наличие, имя, размер и доступную ссылку. В отчёте указать результат и только существенные ограничения; не печатать большие логи.
Документация и установка правил разработки сами по себе не требуют нового APK, изменения версии приложения или развёртывания.
