# Проверка изменений

1. Определить реальный диапазон base..head, задачу и критерии результата. Читать итоговый diff вместе с окружающим кодом, а не пересказ автора.
2. Проверить сценарии пользователя, источники состояния, обработку ошибок и отмены, конкурентный доступ, совместимость данных и границы доверия. Оценить реальное действие тестов.
3. Для замечания указать файл и строку, конкретный сценарий, последствие и доказательство. Отделять подтверждённый дефект от предположения и вопроса.
4. Исправить критические дефекты и нарушения задачи; не расширять работу косметическими переделками. Спорное замечание оценивать по коду и воспроизведению.
5. Проверку выполнять отдельным проходом. Внешнего проверяющего или дополнительных агентов использовать только при разрешении пользователя и доступности инструмента. Не выдавать собственную проверку за независимый аудит.
6. После исправлений запускать только затронутые и обязательные проверки. Не создавать бесконечный цикл аудитов без новых оснований.
Выдать сначала существенные замечания, затем ограничения проверки. Если замечаний нет, сказать «в проверенном диапазоне дефектов не обнаружено», не гарантировать отсутствие всех ошибок.
